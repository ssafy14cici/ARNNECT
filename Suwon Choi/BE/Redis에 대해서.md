# ⚡ Redis에 대해서

## 1. 일반적으로 Redis를 사용하는 이유 
Redis는 "디스크의 한계를 넘는 속도"와 "개발 복잡도를 낮추는 자료구조"를 제공하기 때문에 

### ① 압도적인 속도 (Memory-based)
* **기존 RDB(MySQL):** 디스크(SSD/HDD) I/O가 발생하여 물리적 지연 시간 존재.
* **Redis:** 모든 데이터를 **RAM(메모리)** 에서 처리. 평균 응답 속도가 **1ms(0.001초)** 미만으로, 디스크 기반 DB 대비 수백 배 빠름.
* **주 용도:** 데이터베이스 부하를 줄이는 **캐싱(Caching)**.

### ② 개발 효율을 높이는 자료구조 (Data Structures)
단순 `Key-Value`를 넘어, 복잡한 로직을 미리 구현된 자료구조로 해결 가능.
| 자료구조 | 설명 | 활용 예시 |
| :--- | :--- | :--- |
| **List** | 순서가 있는 대기열 | 메시지 큐, 선착순 이벤트 |
| **Set** | 중복을 허용하지 않는 집합 | 방문자 수 집계 (중복 제거), 태그 관리 |
| **Sorted Set** | 점수에 따라 자동 정렬되는 집합 | **실시간 랭킹**, 인기 검색어 |

### ③ 데이터 수명 관리 (TTL)
* 데이터에 **유효 기간(Time To Live)** 을 설정하여, 시간이 지나면 자동으로 삭제되도록 처리 가능.
* **주 용도:** 세션 관리, 임시 인증번호, 일일 조회수 제한 등.

### ④ 원자성 보장 (Atomicity)
* 싱글 스레드(Single Thread) 기반으로 동작하여, 동시성 문제(Race Condition) 없이 정확한 카운팅 가능.
* **주 용도:** 좋아요 수 집계, 재고 차감.

## 2. 현재 프로젝트에 필요한 이유
본 프로젝트의 핵심 아키텍처인 **[배치 연산 + 실시간 서빙]** 구조에서 Redis는 **시스템의 허리 역할**을 수행한다.

### 🚀 이유 1: 연산과 서빙의 분리 (Decoupling)
* **문제:** AI 모델이나 배치 작업이 전체 작품을 분석하여 랭킹을 매기는 데는 오랜 시간(수십 분)이 소요됨. 사용자 요청 시마다 계산하는 것은 불가능.
* **해결:** 배치가 계산해둔 "완성된 추천 결과(List)"를 Redis에 저장해두고, API 서버는 연산 없이 꺼내주기만 하는 구조(Serving Layer)를 구축.
* **효과:** 사용자가 몰려도 백엔드 연산 부하가 전파되지 않음.

### 🧠 이유 2: "단기 기억" 저장소 (Short-term Context)
* **문제:** "방금 사용자가 클릭한 작품" 정보는 실시간 추천 믹싱(Mixing)을 위해 필수적이나, 10분만 지나도 가치가 급락함. 이를 RDB에 쌓는 것은 낭비.
* **해결:** `recent:view:{userId}` 키에 방금 본 작품 ID를 저장하고 **TTL을 10분**으로 설정.
* **효과:** 별도의 "오래된 데이터 삭제 배치"를 돌릴 필요 없이, 데이터 수명 주기가 자동 관리됨.

### 🛡️ 이유 3: 고속 필터링 (Fast Filtering)
* **문제:** "이미 본 작품은 추천 목록에서 제외"해야 함. RDB에서 매번 이력을 조회(`SELECT`)하는 것은 매우 느림.
* **해결:** 사용자가 본 작품 ID들을 Redis **Set**에 저장해두고 `SISMEMBER` 명령어로 확인.
* **효과:** O(1)의 복잡도로 0.001초 만에 중복 여부 판단 가능.

### 📊 이유 4: 쓰기 지연 (Write-Back)
* **문제:** 인기 작품의 경우 초당 수십 건의 '조회수 증가' 트랜잭션이 발생하여 DB 락(Lock) 유발 가능.
* **해결:** Redis에서 먼저 카운트를 증가(`INCR`)시키고, 일정 주기(예: 1분)마다 DB에 한 번만 반영.
* **효과:** RDB의 쓰기 부하를 획기적으로 감소시킴.

---

Redis의 장점은 다음과 같다
1. 속도가 빠름
2. 데이터 수명을 관리 할 수 있음

이러한 빠르게 정보를 보내고, 휘발성이 강한 데이터를 다루는 지금 프로젝트에서 서빙 속도를 보장할 수 있을 것 같다
