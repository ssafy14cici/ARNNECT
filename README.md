# 작업 규칙 1. 브랜치 분리
## **master**

- 최종, 최신 버전 상태 유지 (오류 XXXXXX)
- 직접 push 금지 ❌❌❌❌❌❌❌❌❌❌
- 폴더 구조
    
    ```
    ├── study/													# 학습자료실
    │   └── 이름/												# 개별 폴더 
    │      ├── 날짜/
    │          ├── 카테고리/
    │              └── 파일
    │
    ├── BE/					
    │   └── 애플리케이션		
    ├── FE/	
    
    ...
    ```
    

## **브랜치 구조**

- **절대 지우지 말기**
- 각 브랜치는 역할별로 분리됨
- 브랜치 switch 또는 checkout해서 각자 작업 진행 → switch 권장
- 공통 리스트
    - FE
    - BE
    - AI
    - CI/CD
    - STUDY
- 작업은 각자 역할브랜치에서
- 작업할 유형 feat/, refactor/, fix/
- 작업할 도메인 or 기능 브랜치 생성해서 각자 작업해주세요 (브랜치 안겹치게 기능 역할 분담하기)
- 예시 1. FE/feat/member → 회원기능 추가 브랜치
- 예시 2. BE/feat/member/auth → 회원의 로그인, 로그아웃, 회원가입 기능 추가 브랜치
